### 문제 5-1 · 웹 서버 요청을 분마다 세어 요청이 급증한 분 찾기

- (가) 실행한 출력 전체를 붙여 넣고, 급증 기준과 요청이 급증한 분(시각과 요청 수)을 적어 주세요.
  - 쓸 내용: ① 출력 전체(코드 상자에 붙여 넣기) ② 급증 기준 ③ 요청이 급증한 분과 요청 수
  - 답: 지난 7일 평균은 분당 2.0건이고, 그 3배인 급증 기준은 6.0건 이상입니다. 09:12에 9건이 들어와 급증으로 탐지됐습니다.

- (나) 🔍 `normalized_events.json` 에서 `time` 이 `2026-11-02 09:12` 로 시작하는 웹 서버(`source` 가 `web`) 줄을 찾아, ① 요청을 보낸 IP 주소와 ② 행동(`action`)별 횟수를 적어 주세요. 그리고 ③ 이 급증을 공격이라고 확정할 수 있는지 이유와 함께 적어 주세요.
  - 쓸 내용: ① 요청을 보낸 IP 주소 ② 행동별 횟수 ③ 공격이라고 확정할 수 있는지와 이유
  - 답: 09:12의 웹 요청 9개는 모두 `203.0.113.50`에서 왔습니다. 행동별로는 `GET /login` 1회, `POST /login` 6회(실패 5회·성공 1회), `GET /admin` 1회, `GET /admin/users` 1회입니다. 공격이라고 확정할 수는 없지만, 같은 주소에서 짧은 시간 동안 로그인을 반복하고 성공한 뒤 관리자 경로를 요청한 점은 의심스러워 조사할 단서가 됩니다. 성공한 계정과 주소의 소유자 등 추가 정보를 확인해야 합니다.

- (다) 🔍 09:20 에도 웹 서버 요청이 3개 있었지만 급증으로 탐지되지 않았습니다. ① 3개를 급증 기준과 비교해 왜 탐지되지 않았는지 적고, ② `normalized_events.json` 에서 09:20 의 `web` 줄 3개가 어떤 요청(IP 주소 · 행동 · 결과)인지 적고, ③ 요청 수만 보는 급증 규칙이 이 요청들을 놓치는 이유를 적어 주세요.
  - 쓸 내용: ① 급증 기준과 비교한 결과 ② 3개 요청의 IP 주소 · 행동 · 결과 ③ 요청 수만 보는 규칙이 놓치는 이유
  - 답: 09:20의 요청은 3건으로 급증 기준 6.0건보다 적어 탐지되지 않았습니다. 세 요청 모두 `198.51.100.90`에서 왔으며, `GET /.env` 실패, `GET /wp-login.php` 실패, `GET /phpmyadmin` 실패입니다. 이 규칙은 분당 요청 수만 비교하므로 요청 수가 적은 경로 탐색은 내용이 의심스러워도 놓칠 수 있습니다. 이런 요청은 경로나 행동을 살피는 별도의 탐지 규칙으로 찾아야 합니다.

### 문제 6-1 · 로그인 실패 알림과 트래픽 급증 알림을 alerts.json 한 파일로 모으기

- (가) 실행한 출력 전체를 붙여 넣고, `alerts.json` 의 내용도 붙여 넣은 뒤 알림이 모두 몇 건인지 적어 주세요.
  - 쓸 내용: ① 출력 전체(첫 번째 코드 상자에 붙여 넣기) ② `alerts.json` 내용(두 번째 코드 상자에 붙여 넣기) ③ 알림 건수
