### 문제 2-1 · 새벽 대량 조회 사건 추적하고 단정할 수 있는지 따지기

- (가) 의심스러운 접근 기록은 몇 번이고, 이상해 보이지만 정상인 줄은 몇 번인가요? 한 줄씩은 정상 같지만 모아서 보면 이상한 줄이 있으면 함께 적어 주세요.
  - 쓸 내용: 「의심: 번호 … / 이상해 보이지만 정상: 번호 … (정상으로 본 이유) / 모으면 이상한 줄: 번호 … (이유)」
  - 답: 의심: 2~5번, 12번, 14~17번 / 이상해 보이지만 정상: 1번 (서비스 계정 `batch-night`가 등록된 서버 `SRV-BATCH`에서 매일 02:00에 맡은 자원 `SETTLE`을 집계하며, 320건 조회도 그 설명과 맞음) / 모으면 이상한 줄: 3~5번은 40건씩 짧은 시간에 연속 조회해 합계 120건이고, 12번과 14~17번은 각각 19건으로 작아 보여도 `SETTLE`을 반복 조회해 합계 95건임.
- (나) 🔍 의심스러운 줄의 근거 필드는 무엇인가요? 필드마다 등록 정보나 같은 계정의 다른 줄과 어떻게 다른지 적어 주세요.
  - 쓸 내용: 근거 필드 세 가지 이상, 필드마다 「어떤 값이 어떤 값과 다른지」
  - 답: 2번은 시각이 02:14로 새벽이고, 기기 `NB-7741`은 `seoyeon`의 등록 기기 `NB-0417`과 다르며, 로그인 방식도 `pw`만 성공해 다른 정상 로그인 기록의 `pw+mfa`와 다름. 3~5번은 같은 계정·기기에서 담당 자원 `SALES`가 아닌 `SETTLE`을 조회했고, 40건씩 3회 연속으로 합계 120건을 조회함. 12번과 14~17번도 등록 기기 `NB-0417`에서 발생했지만 담당 자원이 아닌 `SETTLE`을 조회함. 각 19건은 적어 보여도 다섯 번 합계 95건이고, 14~17번은 약 25분 간격으로 반복됨. 출발 IP가 사내 대역이라는 사실은 등록 기기 또는 실제 사용자 본인임을 증명하지 않음.
- (다) 🔍 방화벽이 막지 못하고 통과한 이유를 5대 원칙의 어느 칸이 비어 있었는지로 설명해 주세요.
  - 쓸 내용: ① 비어 있던 칸 두 개 이상 ② 칸마다 확인했어야 할 것
  - 답: 로그만으로 각 확인이 실제로 없었다고 단정할 수는 없지만, 허용된 기록을 보면 다음 칸의 검증이 부족했거나 허용 정책에 반영되지 않은 것으로 보임. ID/MFA: 2번은 비밀번호만으로 로그인됐으므로 추가 인증으로 본인 여부를 확인했어야 함. Device: `NB-7741`이 등록 기기인지, 보안 상태가 정상인지 확인했어야 함. Application: `seoyeon`에게 `SETTLE` 조회 권한이 있는지 확인하고, 없으면 거부했어야 함. Network: 사내 대역이라는 이유만으로 통과시키지 말고 정산 자원에 접근할 수 있는 구역·경로인지 제한했어야 함. Policy: 새벽 로그인, 새 기기, 짧은 시간의 반복·대량 조회를 위험 신호로 보고 추가 인증이나 제한을 적용했어야 함. 방화벽 차단 기록이 없다는 것은 이 요청들이 차단되지 않았다는 뜻이지, 계정과 자원 권한까지 안전하게 확인됐다는 뜻은 아님.
- (라) 🔍 이 기록만으로 「seoyeon 계정이 도용됐다」고 단정할 수 있나요? 기록으로 확인된 것과 확인하지 못한 것, 그것을 확인하려면 볼 자료를 적어 주세요.
  - 쓸 내용: ① 단정할 수 있는지 ② 기록으로 확인된 것 ③ 확인하지 못한 것 ④ 확인하려면 볼 자료
  - 답: 이 기록만으로 `seoyeon` 계정이 도용됐다고 단정할 수 없음. 확인된 사실은 해당 계정으로 02:14에 등록되지 않은 기기 `NB-7741`에서 비밀번호만으로 로그인이 성공했고, `SETTLE`을 40건씩 세 번 조회했으며, 이후 등록 기기 `NB-0417`에서도 `SETTLE`을 다섯 번 조회해 모두 허용됐다는 것임. 기록만으로는 실제 사용자가 누구인지, `NB-7741` 사용이 승인됐는지, 권한 설정이나 로그에 오류가 있었는지 확인할 수 없음. 인증 시스템의 로그인·MFA·세션 기록, 기기 관리 및 EDR 기록, DHCP·무선망 등의 IP와 기기 연결 기록, 정산 포털의 상세 조회·권한 변경 기록을 확인하고 사용자에게 사실을 확인해야 함.
- (한 줄) 보안 담당에게 보낼 답을 한 문장으로 적어 주세요.
  - 쓸 내용: 보안 담당이 바로 읽을 수 있는 한 문장(무슨 일이 있었고 무엇을 더 확인해야 하는지)
  - 답: `seoyeon` 계정으로 새벽에 미등록 기기에서 비밀번호만 사용해 정산 자료를 대량 조회하고 이후에도 정산 자료를 반복 조회한 기록이 허용됐으나, 계정 도용 여부는 단정할 수 없어 인증·기기·권한 기록을 추가 확인하겠습니다.

### 문제 2-2 · 접속 요청 여섯 개를 5대 원칙의 칸으로 분류하기

- (가) 요청 ① ~ ⑥ 은 각각 5대 원칙 중 어느 칸에서 걸리나요? 걸리지 않고 통과하면 「통과」라고 적어 주세요.
  - 쓸 내용: 「①: … / ②: … / ③: … / ④: … / ⑤: … / ⑥: …」 여섯 개
  - 답: ① ID (비밀번호만으로 관리자 콘솔에 접근하려 하므로 MFA 확인 필요) / ② Device (개인 노트북이고 백신이 꺼져 있으며 패치가 오래됨) / ③ Application (마케팅팀 사용자에게 인사 시스템 권한이 없음) / ④ Network (앱을 거치지 않고 서버 구역 DB에 직접 연결하려 함) / ⑤ Policy (해외 IP와 새벽 03:00 접속이 평소 패턴과 달라 추가 확인 필요) / ⑥ 통과 (MFA, 회사 노트북, 위치·시간, 영업 앱 권한이 모두 정상)
- (나) 🔍 요청 ⑤ 는 ID · Device · Application 이 모두 정상인데 왜 Policy 칸에서 걸리나요?
  - 쓸 내용: ① 정상인 것 ② 평소와 달라진 상황 ③ Policy 칸이 하는 일
  - 답: 로그인은 비밀번호와 MFA를 통과했고, 회사 노트북도 최신이며, 영업 앱을 사용할 권한도 있음. 하지만 해외 IP에서 새벽 03:00에 접속했고 평소에는 서울에서만 접속했다고 하므로 평소와 다른 위험 상황임. Policy는 사용자·기기·앱 권한이 정상이어도 시간과 위치 같은 상황을 살펴 추가 인증을 요구하거나 접근을 제한함.
- (다) 요청 ③ 과 ④ 는 둘 다 가면 안 되는 곳에 닿으려는 시도인데 왜 서로 다른 칸에서 걸리나요?
  - 쓸 내용: ① ③ 이 확인하는 것 ② ④ 가 확인하는 것
  - 답: ③은 사용자가 인사 시스템 앱을 사용할 권한이 있는지를 확인하는 Application 문제임. ④는 앱 권한과 별개로, 개발팀 사용자가 앱을 우회해 서버 구역 DB에 직접 연결할 수 있는 네트워크 경로가 열려 있는지를 확인하는 Network 문제임. 즉 ③은 “이 사용자가 이 앱을 써도 되는가”, ④는 “이 연결 경로로 DB에 직접 닿아도 되는가”를 묻는 것임.
- 이 교시에서 새로 알게 된 것 하나를 적어 주세요.
  - 쓸 내용: 자유롭게
  - 답: 비밀번호와 MFA로 로그인에 성공했더라도 기기 상태, 앱 권한, 네트워크 경로, 접속 시간과 위치를 각각 확인해야 하며, 한 칸의 통과가 모든 접근을 허용하는 뜻은 아님.

### 문제 3-1 · 권한 변경 판단 함수의 점수 직접 정하기

- (가) 내가 채운 코드 여덟 줄을 붙여 넣어 주세요.
  - 쓸 내용: `# ←` 여덟 곳에 채운 코드(점수 세 개 · 역할 검사 두 줄 · MFA 점수 블록 세 줄)
  - 답:

```
HEALTH_POINTS = 50
MFA_POINTS = 25
COUNTRY_POINTS = 25
    if account["role"] != "account_admin":
        return "거부", ["관리자 역할이 아님"]
    if not req["mfa"]:
        score = score + MFA_POINTS
        reasons.append("MFA 안 함")
```

- (나) 🔍 실행해서 나온 요청 A ~ F 의 결정을 적어 주세요. 모두 기대 결정과 같은지도 함께 적어 주세요.
  - 쓸 내용: 「A: … / B: … / C: … / D: … / E: … / F: …」 여섯 개와 「기대 결정과 같음 · 다름」
  - 답: A: 허용 / B: 거부(관리자 역할이 아님) / C: 추가확인(MFA 안 함) / D: 거부(기기 보안 상태 이상) / E: 추가확인(해외에서 접속) / F: 거부(MFA 안 함 + 해외에서 접속). 여섯 건 모두 기대 결정과 같음.
- (다) 🔍 점수 세 개를 정하면서 찾은 조건을 적어 주세요. 점수 하나가 가질 수 있는 범위와, 두 점수의 합이 만족해야 하는 조건이 있나요?
  - 쓸 내용: ① 기기 보안 상태 이상 점수의 범위 ② MFA 점수와 해외 점수의 범위 ③ 둘의 합이 만족해야 하는 조건과 그 이유(요청 몇 번 때문인지)
  - 답: 결정 기준은 50점 이상 거부, 10점 이상 추가확인임. D는 기기 보안 상태 이상만으로 거부되어야 하므로 HEALTH_POINTS는 50점 이상이어야 함. C와 E는 각각 추가확인이어야 하므로 MFA_POINTS와 COUNTRY_POINTS는 각각 10점 이상 50점 미만이어야 함. F는 MFA 미사용과 해외 접속 점수를 합쳐 거부되어야 하므로 두 점수의 합은 50점 이상이어야 함. 예를 들어 현재 설정인 50점, 25점, 25점은 조건을 모두 만족함.
- (라) 🔍 기기 보안 상태 이상은 정산 조회에서는 추가확인인데 권한 변경에서는 거부입니다. 왜 기준이 다른가요?
  - 쓸 내용: ① 정산 조회에서 그 신호의 점수와 결정 ② 내가 정한 권한 변경 점수와 결정 ③ 기준이 다른 이유
  - 답: 정산 조회에서는 기기 보안 상태 이상이 40점이라 추가확인이고, 권한 변경에서는 50점으로 정해 D가 거부됨. 계정 권한 변경은 계정의 접근 범위를 바꿀 수 있어 정산 조회보다 영향과 위험이 크므로, 같은 기기 이상 신호라도 더 엄격하게 판단함.

### 문제 3-2 · 요청 7건을 한꺼번에 판정해 건수 세기

- (가) 실행해서 나온 출력 전체를 붙여 넣어 주세요.
  - 쓸 내용: 거부 · 추가확인 줄, 건수 줄, 이유별 건수 줄 전체
  - 답:

```
[추가확인] 2 seoyeon ['대량 조회 (+30)']
[거부] 3 seoyeon ['이 계정에 등록된 기기가 아님']
[거부] 4 dami ['재직 중인 계정이 아님']
[추가확인] 5 junho ['기기 보안 상태 이상 (+40)']
[거부] 6 junho ['해외에서 접속 (+30)', '새벽 접속 (+20)']
[거부] 7 seoyeon ['이 계정에 등록된 기기가 아님']
허용 1 건 / 추가확인 2 건 / 거부 4 건
거부 이유별 건수 {'이 계정에 등록된 기기가 아님': 2, '재직 중인 계정이 아님': 1, '해외에서 접속 (+30)': 1, '새벽 접속 (+20)': 1}
```

- (나) 🔍 거부된 요청 중 필수 조건에서 바로 거부된 것과 점수가 쌓여서 거부된 것은 각각 몇 번 요청이고 이유가 무엇인가요?
  - 쓸 내용: ① 필수 조건으로 거부된 요청 번호와 이유 ② 점수로 거부된 요청 번호와 이유 목록
  - 답: 필수 조건에서 바로 거부: 3번(요청 기기가 `seoyeon`의 등록 기기와 다름), 4번(`dami` 계정이 퇴사 상태), 7번(요청 기기가 `seoyeon`의 등록 기기와 다름). 점수로 거부: 6번(해외 접속 30점 + 새벽 접속 20점 = 50점). 따라서 필수 조건 거부 3건, 점수 거부 1건임.
- (다) 🔍 거부 이유별 건수에서 가장 많은 이유는 무엇이고, 이 숫자는 보안 담당에게 무엇을 알려 주나요?
