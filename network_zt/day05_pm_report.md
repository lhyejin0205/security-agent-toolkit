### 문제 5-1 · 지연 · 지터 · 손실을 직접 계산하기

- (가) 회선 X 와 Y 의 평균 지연과 지터(이웃한 두 값의 차이의 평균), 회선 Z 의 손실률을 각각 구해 적어 주세요.
  - 쓸 내용: 「X: 평균 … ms · 지터 … ms / Y: 평균 … ms · 지터 … ms / Z: 손실 … %」
  - 답: X: 평균 30 ms · 지터 1 ms (차이: 1, 2, 1, 0 ms) / Y: 평균 26 ms · 지터 38 ms (차이: 40, 38, 36, 38 ms) / Z: 손실 40% (응답 없음 2회 ÷ 보낸 5회 × 100)
- (나) 🔍 평균 지연만 보면 Y 가 더 좋아 보입니다. 화상회의에는 어느 회선이 더 나쁠까요? 왜 그런가요?
  - 쓸 내용: ① 회선 이름 하나 ② 지연 · 지터 숫자를 써서 이유
  - 답: 회선 Y가 더 나쁩니다. 평균 지연은 Y가 26 ms로 X의 30 ms보다 낮아 더 빨라 보이지만, 지터가 38 ms로 X의 1 ms보다 훨씬 커 응답 시간이 들쭉날쭉합니다. 그래서 화상회의 음성이나 화면이 끊길 수 있습니다.

## 6교시 · 코드로 계산과 판정

### 문제 6-1 · 지터 함수 직접 만들기

- (가) 직접 만든 `jitter` 함수를 독스트링과 함께 아래 코드 블록에 붙여 넣어 주세요.
  - 쓸 내용: 독스트링을 쓴 함수를 복사해 아래 코드 블록에 붙여 넣기
  - 답:

```
def jitter(got):
    """받은 응답 시간들의 이웃한 차이 평균인 지터를 구한다.

    입력: 응답을 받은 시간 값들의 리스트 got
    리턴: 이웃한 두 응답 시간 차이의 평균
    """
    total = 0
    for i in range(1, len(got)):
        total += abs(got[i] - got[i - 1])
    return total / (len(got) - 1)
```
- (나) 함수를 채운 뒤 실행해 나온 세 줄을 그대로 옮겨 적어 주세요.
  - 쓸 내용: 터미널 출력 세 줄을 복사해 붙여 넣기
  - 답:

```
회선 A | 지연 21.9 ms | 지터 1.1 ms | 손실 0 %
회선 B | 지연 42.3 ms | 지터 54.3 ms | 손실 0 %
회선 C | 지연 41.0 ms | 지터 1.7 ms | 손실 30 %
```
- (다) `jitter` 함수의 리턴값은 무엇이고, `measure` 의 어느 줄에서 어떻게 쓰이나요?
  - 쓸 내용: ① 리턴하는 값이 무엇인지 ② 그 값을 받는 줄(`measure` 안)
  - 답: `jitter`는 이웃한 응답 시간 차이의 평균(지터)을 리턴합니다. `measure` 안의 `jitter_value = jitter(got)` 줄에서 응답값 리스트 `got`을 넘겨받고, 리턴된 지터를 `jitter_value`에 저장해 출력에 사용합니다.

### 문제 6-2 · 세 회선을 화상회의 기준으로 판정하기

- (가) 세 회선의 판정 결과(적합 · 부적합)와 걸린 기준을 각각 적어 주세요.
  - 쓸 내용: 「A: … / B: … (걸린 기준 …) / C: … (걸린 기준 …)」
  - 답: A: 적합 / B: 부적합 (걸린 기준: 지터) / C: 부적합 (걸린 기준: 손실)

```
회선 A → 적합
회선 B → 부적합 (걸린 기준: 지터)
회선 C → 부적합 (걸린 기준: 손실)
```
- (나) 회선 C 는 지연과 지터가 작은데도 왜 부적합인가요? 어제(10/15) 오후 문제 5-2 에서 본 것과 연결해 적어 주세요.
  - 쓸 내용: ① C 의 손실률과 기준 ② 손실이 통신에 주는 영향 한 가지
  - 답: 회선 C의 손실률은 30%로 기준인 1% 이하를 넘기 때문에 부적합입니다. 손실된 패킷은 다시 보내야 하고, 화상회의에서는 음성이나 화면이 끊길 수 있습니다.
- (다) 🔍 `ok` 를 `and` 로 이은 이유는 무엇인가요? `or` 로 이으면 회선 B 의 판정이 어떻게 달라지나요?
  - 쓸 내용: ① `and` 로 이은 이유 ② `or` 로 이으면 B 의 판정이 어떻게 달라지는지
  - 답: 세 기준을 모두 지켜야 적합이므로 `and`로 연결합니다. `or`로 바꾸면 회선 B는 지연과 손실 기준을 통과하기만 해도 전체가 참이 되어 적합으로 잘못 판정됩니다. 실제로 B는 지터 54.3 ms로 기준 30 ms를 넘습니다.
- (한 줄) 고객에게 보낼 답을 한 문장으로 적어 주세요.
  - 쓸 내용: 고객이 바로 읽을 수 있는 한 문장(어느 회선이 되고 안 되는지, 이유 한 가지)
  - 답: 화상회의에는 회선 A가 적합하고 B는 지터가 54.3 ms로, C는 손실률이 30%로 기준을 넘어 부적합합니다.
- 이 교시에서 새로 알게 된 것 하나를 적어 주세요.
  - 쓸 내용: 자유롭게
  - 답: 여러 기준을 모두 만족해야 할 때는 `and`를 쓰며, `or`를 쓰면 한 기준만 통과해도 전체가 참이 됩니다.

  - 답: 바깥(통신사·해외) 쪽입니다. 사내 공유기와 방화벽(1·2번 홉)은 1~2 ms이고, 지연이 통신사 중계 장비(4번 홉)와 해외 연결 지점(5번 홉) 사이에서 증가합니다.

  - 답: 바로 다음 5번 홉은 7 ms로 다시 작아집니다. 실제로 경로가 느려졌다면 뒤의 홉들도 큰 시간이 이어져야 하므로, 4번 장비가 자기 tracert 응답만 늦게 보낸 것이며 실제 통신 지연이라고 단정할 수 없습니다.

- SaaS 접속이 느린 원인 구간과 그 근거를 적어 주세요.
  - 쓸 내용: ① 원인 구간 ② 근거(tracert 에서 뛴 값) ③ 사내 구간이 정상이라는 근거
  - 답: 4번 통신사 중계 장비와 5번 해외 연결 지점 사이에서 지연이 증가한 것으로 보입니다. tracert 시간이 4번에서 6 ms, 5번에서 48 ms로 뛴 뒤 6번 49 ms, 7번 50 ms로 높게 유지됩니다. 사내 공유기와 방화벽인 1·2번 홉은 각각 1 ms, 2 ms입니다.

### 4. 한계와 다음 확인

- 이 진단으로 알 수 없는 것 하나와, 다음에 확인할 것 하나를 적어 주세요.
  - 쓸 내용: ① 알 수 없는 것(예: 한 시각의 값이라는 점) ② 다음 확인(시간대를 바꿔 다시 재기 · 구간 운영자에게 확인 요청)
  - 답: 한 번의 측정만으로 지연이 계속되는지, 통신사 구간이 확정 원인인지 알 수 없습니다. 다른 시간대에도 같은 ping·tracert 측정을 반복하고, 지연이 재현되면 측정 결과를 첨부해 통신사에 확인을 요청합니다.
