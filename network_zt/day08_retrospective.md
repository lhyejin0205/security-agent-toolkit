# 2과목 회고 (10/21(수))
## 잘 이해한 것
- Docker의 포트 표기에서 호스트 포트와 컨테이너 포트를 구별하고, `127.0.0.1` 바인딩과 `0.0.0.0` 바인딩의 노출 범위를 비교하는 것
- `docker ps`의 `PORTS`, `docker inspect`의 `HostIp`, `curl` 결과, `docker logs`를 함께 봐서 연결 설정 문제와 실제 응답을 확인하는 것
- 로그에 적힌 사실과 그 사실로 추정하는 원인을 구분하고, 원인을 단정하지 않은 채 확인할 기록을 정하는 것
## 막힌 것
- 처음에는 `PORTS`의 `호스트포트->컨테이너포트`와 `HostIp`가 무엇을 뜻하는지 헷갈렸다. `000`은 HTTP 상태 코드가 아니라 HTTP 응답을 받지 못했다는 뜻이며, `curl` 오류와 서버가 반환한 HTTP 상태 코드를 구분해야 했다.
- 컨테이너가 `Up`이어도 서비스가 듣는 컨테이너 포트와 매핑 포트가 다르면 응답하지 않을 수 있었다. `docker ps`뿐 아니라 `docker logs`와 정상 포트로 실행한 비교 서버까지 확인해야 원인을 찾을 수 있었다.
## 3과목과 캡스톤에서 이어 갈 것
- `day06_zt_scenario.md`의 최소권한 기준과 점수 결과를 3과목 접근통제 자동화의 권한 설계 출발점으로 활용한다. 캡스톤에서도 정책 로그와 실제 접근 결과를 함께 확인하고, 확인된 사실과 가설을 구분하는 흐름을 이어 간다.
