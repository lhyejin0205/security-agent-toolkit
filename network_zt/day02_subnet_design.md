## 2교시 · IP 주소 · 사설과 공인

### 문제 2-1 · 내 IP 를 2진수로

- (가) 두 번째 파일(`warmup_2_1b.py`, 내 IPv4 주소)의 출력 네 줄:192 11000000, 168 10101000, 10 00001010, 25 00011001
- (나-1) `format(number, "08b")` 가 마디 하나의 10진수를 어떤 형태의 글자로 바꾸는지, 내 출력 한 줄을 예로 들어 설명하세요.
  - 답: 마디 하나의 10진수를 2진수 문자열로 바꾸고, 앞에 0을 채워 8자리로 맞춥니다. 예를 들어 `192`는 `11000000`으로 출력됩니다.
- (나-2) `"08b"` 에서 `08` 을 빼고 `"b"` 만 쓰면 `10` 은 어떻게 출력되나요?
  - 답: `1010`으로 출력됩니다. `"b"`만 쓰면 2진수로 변환하지만, 앞에 0을 채우거나 8자리로 맞추지는 않습니다.
- (나-3) 마디마다 8자리로 맞춰 써야 하는 이유를 설명하세요.
  - 답: IPv4 주소는 4개의 마디로 이루어지고, 마디마다 8비트를 사용하므로 전체가 32비트입니다. 각 마디를 8자리로 맞춰야 비트 수와 마디 경계를 정확히 나타낼 수 있습니다.
- (다-1) IPv4 주소가 32비트라는 것과 마디 하나가 `0` ~ `255` 사이의 값만 가진다는 것은 어떻게 이어지나요? 마디 수와 비트 수를 근거로 설명하세요.
  - 답: IPv4 주소는 마디가 4개이고, 각 마디는 8비트이므로 `4 × 8 = 32`비트입니다. 8비트로 나타낼 수 있는 값은 `2⁸ = 256`가지이므로 각 마디의 값은 `0`부터 `255`까지입니다.
- (다-2) 32비트로 만들 수 있는 주소의 개수: `2³² = 4,294,967,296`개
- (다-3) 그 개수가 나오는 계산 과정을, 비트 한 자리에 들어갈 수 있는 값의 가짓수와 자리 수를 넣어 단계별로 설명하세요.
  - 답: 비트 한 자리에는 `0` 또는 `1`이 들어가므로 2가지입니다. 서로 독립적인 비트가 32자리 있으므로 가능한 조합의 수는 `2 × 2 × ... × 2`(32번), 즉 `2³²`입니다. 따라서 총 `4,294,967,296`개의 주소를 만들 수 있습니다.
- (다-4) 이 수의 한계가 사설 IP 와 NAT 를 쓰게 된 것과 어떻게 이어지는지 설명하세요.
  - 답: IPv4 주소의 수는 약 43억 개로 한정되어 있어 인터넷에 연결되는 모든 기기에 공인 주소를 하나씩 배정하기 어렵습니다. 사설 IP 주소는 여러 내부 네트워크에서 재사용하고, NAT는 여러 기기가 사설 IP를 사용하면서 외부 통신 때는 하나 또는 소수의 공인 IP를 함께 사용하도록 하여 공인 IPv4 주소를 절약합니다.

### 문제 2-2 · 내 주소는 사설일까 — 인터넷이 보는 내 주소

- (가) `ipconfig` 의 내 IPv4 주소 · `curl` 로 본 공인 IP: `192.168.100.127` · `1.245.252.171`
- (나-1) 🔍 내 IPv4 주소는 2.2 표의 어느 범위에 들어가며, 그래서 사설과 공인 가운데 무엇인가요? 범위의 시작 주소와 끝 주소를 근거로 판정하세요.
  - 답: 내 IPv4 주소 `192.168.100.127`은 `192.168.0.0`부터 `192.168.255.255`까지의 사설 IP 범위에 들어가므로 사설 IP입니다.
- (나-2) `curl` 로 본 주소는 사설과 공인 가운데 무엇인가요? 2.2 표의 세 범위와 맞춰 본 근거를 들어 설명하세요.
  - 답: `curl`로 본 주소 `1.245.252.171`은 `10.0.0.0`~`10.255.255.255`, `172.16.0.0`~`172.31.255.255`, `192.168.0.0`~`192.168.255.255`의 사설 IP 범위 어디에도 해당하지 않으므로 공인 IP입니다.
- (나-3) 관제 로그의 출발지 주소가 `172.20.5.6` 과 `172.32.5.6` 이라면, 각각 내부망 장비와 외부 주소 가운데 무엇으로 먼저 분류해야 하나요? 2.2 표를 근거로 설명하세요.
  - 답: `172.20.5.6`은 둘째 마디 `20`이 `16`~`31` 범위에 있으므로 사설 IP, 즉 내부망 장비로 먼저 분류합니다. `172.32.5.6`은 둘째 마디 `32`가 범위를 벗어나므로 공인 IP, 즉 외부 주소로 먼저 분류합니다.
- (다-1) 외부 서버 로그에 남은 출발지 IP 만으로는 내부망의 어느 PC 인지 특정할 수 없는 이유를 NAT 의 동작으로 설명하세요.
  - 답: NAT는 내부 PC가 외부로 통신할 때 사설 출발지 IP를 공유기의 공인 IP로 바꾸어 보냅니다. 여러 PC가 같은 공인 IP를 공유하므로 외부 서버 로그에는 공인 IP만 남아 어느 PC가 통신했는지 알 수 없습니다. 특정하려면 통신 시각과 NAT 변환 기록(공인 IP·포트와 내부 사설 IP·포트의 대응)을 함께 확인해야 합니다.
- (다-2) 정적 NAT 과 동적 NAT 은 사설 IP 와 공인 IP 를 연결하는 방식이 어떻게 다른가요?
  - 답: 정적 NAT은 사설 IP 하나와 공인 IP 하나를 고정해서 일대일로 연결합니다. 동적 NAT은 사용할 수 있는 공인 IP 주소 풀에서 통신할 때마다 사용 가능한 주소를 골라 임시로 연결합니다.
- (다-3) 사원 PC 여러 대가 인터넷을 쓸 때는 동적 NAT 을 쓰는 이유는 무엇인가요? 동적 NAT 환경에서 외부 로그의 공인 IP 로 PC 를 특정하려면 무엇을 함께 봐야 하는지와 이어서 설명하세요.
  - 답: 사원 PC는 외부에서 항상 같은 주소로 접속할 서버가 아니므로 공인 IP를 PC마다 고정할 필요가 없습니다. 동적 NAT을 쓰면 공인 IP를 필요한 통신에 나누어 배정해 주소를 효율적으로 쓸 수 있습니다. 외부 로그의 공인 IP만으로는 해당 시각에 어떤 PC가 사용했는지 알 수 없으므로, 통신 시각과 NAT 변환 기록을 함께 확인해야 합니다.
- (다-4) 인터넷에서 회사 내부망의 웹 서버에 접속하게 하려면 정적 NAT 과 동적 NAT 가운데 어느 방식이 맞는지 이유와 함께 설명하세요.
  - 답: 정적 NAT이 맞습니다. 내부 웹 서버에 연결된 공인 IP가 고정되어야 외부 사용자가 늘 같은 주소로 서버를 찾아 접속할 수 있기 때문입니다.

### 이 교시에 새로 안 것

- 이 교시에서 새로 알게 된 것: IPv4 주소는 32비트이며, 주소 수가 한정되어 있어 사설 IP와 NAT를 활용한다는 것을 알게 되었다. 사설 IP는 내부망에서 사용하고, NAT는 외부 통신 시 공인 IP로 변환한다. 따라서 외부 로그만으로 내부 PC를 찾으려면 통신 시각과 NAT 변환 기록도 확인해야 한다.

## 3교시 · 서브넷 마스크 · CIDR

### 문제 3-1 · 내 서브넷 마스크 읽기

- (가-1) 내 서브넷 마스크 · CIDR · 주소 수 · 쓸 수 있는 수: `255.255.0.0` · `/16` · `65,536`개 · `65,534`개
- (가-2) 내 IPv4 주소의 망 부분 · 장비 부분: 망 부분 `192.168` · 장비 부분 `100.127`
- (나-1) 🔍 내 서브넷 마스크를 2진수로 펼쳤을 때 1 인 비트와 0 인 비트가 각각 주소의 어느 부분을 가리키는지, 1 이 8개인 마디의 수를 근거로 설명하세요.
  - 답: `255.255.0.0`을 2진수로 쓰면 `11111111.11111111.00000000.00000000`입니다. 앞의 두 마디에 있는 16개의 1비트는 망 부분을, 뒤의 두 마디에 있는 16개의 0비트는 장비 부분을 가리킵니다.
- (나-2) 내 마스크에서 CIDR 숫자가 어떤 계산으로 나오는지 1 이 8개인 마디의 수를 넣어 설명하세요.
  - 답: 마스크에서 1이 8개인 마디가 두 개이므로 `2 × 8 = 16`입니다. 따라서 CIDR 표기는 `/16`입니다.
- (나-3) 같은 교실의 다른 PC 와 비교했을 때, 망 부분과 장비 부분 가운데 어느 쪽이 같고 어느 쪽이 다른가요? 그렇게 되는 이유를 「같은 망」의 뜻과 이어서 설명하세요.
  - 답: 같은 망에 있고 같은 `/16` 마스크를 쓰는 교실의 PC라면 망 부분인 앞 두 마디(`192.168`)는 같고, 장비 부분인 뒤 두 마디는 달라야 각 PC를 구분할 수 있습니다. 마스크로 계산한 망 부분이 같다는 것이 같은 망이라는 뜻입니다.
- (다-1) 내 마스크를 기준으로 `192.168.10.25` 와 `192.168.20.25` 가 같은 망인지 판정하고, 비교해야 하는 마디를 짚어 근거를 설명하세요.
  - 답: 같은 망입니다. 내 마스크는 `/16`이므로 앞의 두 마디를 비교하며, 두 주소 모두 `192.168`로 같기 때문입니다.
- (다-2) 같은 두 주소를 `/24` 마스크로 판정하면 결과가 어떻게 달라지나요?
  - 답: 다른 망으로 판정됩니다. `/24`에서는 앞의 세 마디가 망 부분인데, `192.168.10`과 `192.168.20`이 다르기 때문입니다.
- (다-3) 마스크에 따라 판정이 달라진다는 사실이 통신 경로와 방화벽 규칙을 정할 때 왜 중요한지 설명하세요.
  - 답: 같은 망으로 판정되면 장비는 보통 게이트웨이 없이 상대에게 직접 보낼 수 있고, 다른 망이면 게이트웨이를 거쳐야 합니다. 방화벽 규칙도 망의 범위를 기준으로 적용될 수 있으므로 마스크를 잘못 판단하면 통신 경로가 달라지거나 의도하지 않은 주소가 허용·차단될 수 있습니다.

### 문제 3-2 · 내 망 범위

- (가) 두 번째 파일(`warmup_3_2b.py`)의 내 주소/CIDR · 출력 세 줄: `192.168.100.127/16` · `255.255.0.0` · `192.168.0.0` · `192.168.255.255`
- (나-1) 출력 세 줄이 각각 3.2 의 ① ~ ④ 가운데 어느 단계의 값인지: 첫째 줄은 ① 마스크, 둘째 줄은 ③ 네트워크 주소, 셋째 줄은 ③ 브로드캐스트 주소입니다. ④ 장비에 줄 수 있는 범위는 `192.168.0.1`~`192.168.255.254`입니다.
- (나-2) 내 주소에서 `0` · `255` 로 바뀐 마디: 셋째와 넷째 마디가 네트워크 주소에서는 `0`, 브로드캐스트 주소에서는 `255`로 바뀝니다.
- (나-3) 둘째 줄 값이 3.2 의 AND 연산으로 어떻게 나오는지 설명하세요.
  - 답: 주소 `192.168.100.127`과 마스크 `255.255.0.0`을 2진수로 바꾸어 같은 자리끼리 AND 합니다. 앞의 두 마디는 마스크가 모두 1이어서 `192.168`이 유지되고, 뒤의 두 마디는 마스크가 모두 0이어서 0이 됩니다. 따라서 네트워크 주소는 `192.168.0.0`입니다.
- (나-4) 왜 그 마디만 바뀌고 나머지 마디는 그대로인지 망 부분과 장비 부분으로 설명하세요.
  - 답: `/16`에서 앞의 두 마디(`192.168`)가 망 부분이라 그대로 유지되고, 뒤의 두 마디(`100.127`)는 장비 부분이라 네트워크 주소에서는 `0`, 브로드캐스트 주소에서는 `255`로 바뀝니다.
- (다-1) `ipconfig` 의 내 기본 게이트웨이 주소가 둘째 줄과 셋째 줄 사이에 있는지(예 · 아니오): 예 (`192.168.1.1`)
- (다-2) 게이트웨이 주소가 이 범위 안에 있어야 하는 이유를 설명하세요.
  - 답: PC는 같은 망의 게이트웨이에 다른 망으로 갈 패킷을 전달하므로 게이트웨이는 내 망에서 장비에 할당할 수 있는 범위에 있어야 합니다. `192.168.1.1`은 `192.168.0.1`~`192.168.255.254` 안에 있습니다.
- (다-3) 게이트웨이 주소를 둘째 줄의 네트워크 주소나 셋째 줄의 브로드캐스트 주소로 잘못 설정하면 왜 문제가 되는지, 두 주소의 역할을 들어 설명하세요.
  - 답: 네트워크 주소 `192.168.0.0`은 망 전체를 가리키고, 브로드캐스트 주소 `192.168.255.255`는 망 안의 모든 장비를 대상으로 하므로 둘 다 개별 장비의 주소로 쓸 수 없습니다. 게이트웨이는 패킷을 전달할 특정 장비여야 하므로 둘 중 하나로 설정하면 정상적인 통신이 되지 않습니다.

### 이 교시에 새로 안 것

- 이 교시에서 새로 알게 된 것: 서브넷 마스크 `/16`은 앞의 두 마디를 망 부분, 뒤의 두 마디를 장비 부분으로 나눈다는 점을 알게 되었다. 네트워크 주소와 브로드캐스트 주소 사이가 장비에 할당할 수 있는 범위이며, 기본 게이트웨이도 그 범위 안의 주소를 사용한다.

## 4교시 · 서브네팅

### 문제 4-1 · 반으로 나누기 `/25`

- (가) 출력 두 줄: `192.168.50.0/25` · `192.168.50.128/25`
- (나-1) 4.1 표와 맞춰 쓴 블록마다의 범위: `192.168.50.0/25`는 `.0`~`.127`, `192.168.50.128/25`는 `.128`~`.255`입니다.
- (나-2) 블록 이름 `192.168.50.128/25` 의 `/` 앞 주소는 그 블록에서 어떤 주소인가요? 설명하세요.
  - 답: `/` 앞의 `192.168.50.128`은 두 번째 블록의 네트워크 주소이자 블록에서 가장 작은 주소입니다.
- (나-3) 두 블록이 `.128` 에서 나뉘는 이유를 블록 하나의 주소 수로 설명하세요.
  - 답: `/25` 블록 하나에는 주소가 128개 있습니다. 첫 블록은 `.0`부터 `.127`까지 128개이므로 다음 블록은 바로 다음 주소인 `.128`에서 시작합니다.
- (나-4) 쓸 수 있는 수(126)만큼씩 자르면 안 되는 이유를 설명하세요.
  - 답: 블록에는 장비에 쓸 수 없는 네트워크 주소와 브로드캐스트 주소도 포함되므로, 경계는 사용 가능 주소 126개가 아니라 전체 주소 128개를 기준으로 정해야 합니다. 126개씩 자르면 서브넷 경계가 어긋납니다.
- (다-1) 4.1 첫 표의 `/26` 줄에서 읽은 주소 수 · 장비에 쓸 수 있는 수: 64개 · 62개
- (다-2) 두 수가 2 만큼 다른 이유를 빠지는 두 주소의 역할로 설명하세요.
  - 답: 주소 64개 중 네트워크 주소는 망 전체를 나타내고 브로드캐스트 주소는 망 안의 모든 장비를 대상으로 하므로, 이 두 주소는 개별 장비에 할당할 수 없습니다. 따라서 사용 가능 주소는 2개 적은 62개입니다.
- (다-3) 장비 64대인 부서에 `/26` 블록을 주면 어떤 설계 실수가 되는지 설명하세요.
  - 답: `/26`은 주소가 64개지만 장비에 할당할 수 있는 주소는 62개뿐이므로 64대 모두에 주소를 줄 수 없습니다. 장비 수보다 작은 블록을 배정한 설계 실수이며, 더 큰 `/25` 블록을 배정해야 합니다.

### 문제 4-2 · 겹침 검사

- (가) 첫 파일 출력 · 두 번째 파일(`warmup_4_2b.py`) 출력: `False` · `True`
- (나-1) 🔍 운영팀을 `192.168.50.64/26` 으로 바꾸자 `True` 가 나온 이유를 두 망의 범위를 비교해 설명하세요.
  - 답: 개발팀 망 `192.168.50.0/25`의 범위는 `.0`~`.127`이고, 바꾼 운영팀 망 `192.168.50.64/26`은 `.64`~`.127`입니다. 운영팀 망이 개발팀 망 안에 포함되어 주소 범위가 겹치므로 `overlaps()`가 `True`를 출력합니다.
- (나-2) 두 망이 겹치는 주소 구간: `192.168.50.64`~`192.168.50.127`
- (다-1) 부서 망이 겹쳐 두 장비가 같은 IP 주소를 받으면 통신에는 어떤 문제가 생기는지 설명하세요.
  - 답: 같은 IP를 가진 장비가 둘이면 네트워크가 목적지 장비를 구별하기 어려워 패킷이 엉뚱한 장비에 전달되거나 통신이 끊기고 불안정해질 수 있습니다. 운영체제에서 IP 주소 충돌 경고가 나타날 수도 있습니다.
- (다-2) 같은 상황이 관제 로그 해석에는 어떤 문제를 일으키는지 설명하세요.
  - 답: 로그에 같은 IP 주소가 기록되어도 그 시점에 어느 부서의 어떤 장비가 통신했는지 구별하기 어려워집니다. 그 결과 사고 원인 추적과 부서별 방화벽 규칙 적용이 부정확해질 수 있습니다.

### 이 교시에 새로 안 것

- 이 교시에서 새로 알게 된 것: 서브넷끼리 주소 범위가 겹치면 IP 충돌과 통신 장애가 생길 수 있고, 로그만으로 장비나 부서를 특정하기 어려워진다는 것을 알게 되었다. 따라서 주소를 나눌 때 각 부서의 망 범위가 겹치지 않는지 확인해야 한다.

## 5교시 · 스위치와 라우터

### 문제 5-1 · ARP 캐시에서 게이트웨이 찾기

- (가) 기본 게이트웨이 줄의 IP · MAC 주소 · `8.8.8.8` 줄이 있었나: `192.168.1.1` · `00-10-f3-a3-fc-96` · 없음
- (나) 🔍 방금 `8.8.8.8` 로 보냈는데도 ARP 캐시에는 내 망(학원 PC 는 앞 두 마디 `192.168`)의 장비만 있고 `8.8.8.8` 줄이 없는 이유를, 다른 망으로 보내는 프레임의 목적지 MAC 과 이어서 설명하세요.
  - 답: `8.8.8.8`은 내 망 바깥에 있으므로 PC는 그 서버의 MAC 주소를 찾지 않고, 패킷을 기본 게이트웨이로 보냅니다. 따라서 이더넷 프레임의 목적지 MAC은 게이트웨이(`192.168.1.1`)의 MAC이고, ARP 캐시에는 게이트웨이 같은 내 망 장비의 IP와 MAC만 기록됩니다.
- (다-1) MAC 주소와 IP 주소는 각각 누가 정하나요?
  - 답: MAC 주소는 보통 네트워크 장비의 제조사가 인터페이스에 부여하고, IP 주소는 네트워크 관리자나 DHCP 서버가 네트워크 설정에 따라 할당합니다. (일부 장비에서는 MAC 주소를 소프트웨어로 바꿔 보이게 할 수도 있습니다.)
- (다-2) 패킷이 다른 망으로 건너갈 때 목적지 IP 주소와 MAC 주소가 바뀌는지 그대로인지 비교해 설명하세요.
  - 답: 목적지 IP 주소는 최종 목적지인 `8.8.8.8`로 유지됩니다. 반면 MAC 주소는 한 망에서 다음 장비로 전달할 때 쓰는 주소이므로, 라우터를 지날 때마다 다음 홉의 MAC 주소로 바뀝니다.
- (다-3) ARP 가 MAC 주소를 알아낼 때 질문은 브로드캐스트로 보내고 답은 한 장비만 하는 이유를 설명하세요.
  - 답: ARP 질문을 보낼 때는 해당 IP의 MAC 주소를 아직 모르므로 같은 망의 모든 장비에게 브로드캐스트합니다. 그 IP를 가진 장비만 자신에게 온 질문임을 확인하고 응답하면 되므로, 답은 그 한 장비가 보냅니다.

### 문제 5-2 · 스위치의 MAC 주소 표 읽기

- (가) 첫 파일 출력 · 두 번째 파일(`"AA"`) 출력: `모든 포트로` · `포트 1 로만`
- (나-1) 두 출력이 다른 이유를 MAC 주소 표에 적힌 내용과 5.3 의 ② · ③ 단계로 설명하세요.
  - 답: MAC 주소 표에는 `AA`만 1번 포트로 기록되어 있습니다. 첫 파일의 목적지 `BB`는 표에 없으므로 ②에서 찾지 못해 ③의 플러딩(모든 포트로)이 실행됩니다. 두 번째 파일의 목적지 `AA`는 표에 있으므로 해당 포트 하나로만 보냅니다.
- (나-2) 둘째 출력에 `AA` 가 아니라 숫자가 나온 이유를 딕셔너리의 키와 값으로 설명하세요.
  - 답: 딕셔너리에서 `AA`는 키이고 `1`은 그 키에 대응하는 값입니다. `mac_table[dest]`는 `dest`가 `AA`일 때 키 `AA`에 연결된 값 `1`을 꺼내므로 숫자가 출력됩니다.
- (나-3) 그 숫자는 실제 스위치에서 무엇을 뜻하나요?
  - 답: `1`은 목적지 MAC 주소 `AA`가 연결된 스위치의 포트 번호, 즉 1번 포트를 뜻합니다.
- (다-1) 플러딩은 어떤 조건에서 일어나나요?
  - 답: 목적지 MAC 주소가 MAC 주소 표에 없을 때 스위치는 프레임이 들어온 포트를 제외한 나머지 포트로 보내는데, 이를 플러딩이라고 합니다. 브로드캐스트 프레임도 여러 포트로 전달됩니다.
- (다-2) 5.3 의 예처럼 처음에는 플러딩하던 스위치가 그다음부터 한 포트로만 보내게 되는 과정을 설명하세요.
  - 답: 처음 `CC → DD` 프레임이 왔을 때 스위치는 출발지 `CC`와 들어온 2번 포트만 학습합니다. 목적지 `DD`는 아직 표에 없어 플러딩합니다. 이후 `DD → CC` 응답이 4번 포트로 들어오면 출발지 `DD`와 4번 포트를 학습하고, 이미 알고 있는 `CC`의 2번 포트로만 보냅니다. 다음부터는 `DD`로 가는 프레임도 4번 포트로만 전달할 수 있습니다.
- (다-3) 플러딩이 많아지면 망의 성능과 보안에 각각 어떤 문제가 생기는지 예를 들어 설명하세요.
  - 답: 성능 면에서는 프레임 복사본이 여러 포트로 퍼져 불필요한 트래픽이 늘고 망이 느려질 수 있습니다. 보안 면에서는 원래 다른 장비로 가야 할 프레임이 여러 장비에도 전달되어, 같은 망의 장비가 통신 내용을 엿볼 기회가 생길 수 있습니다.

### 이 교시에 새로 안 것

- 이 교시에서 새로 알게 된 것: 스위치는 프레임의 출발지 MAC 주소와 들어온 포트를 학습하고, 목적지 MAC 주소가 표에 있으면 해당 포트로만 보낸다. 목적지를 모르면 플러딩하므로, MAC 주소 표는 통신 효율과 보안에 모두 중요하다.

## 6교시 · VLAN · 라우팅 표

### 문제 6-1 · 내 PC 의 기본 게이트웨이와 첫 홉

- (가) `ipconfig` 의 기본 게이트웨이 주소 · `tracert` 1번 홉의 주소: `192.168.1.1` · `192.168.1.1`
- (나-1) 🔍 두 주소가 일치한다는 것은 이 PC 의 트래픽 경로에 대해 무엇을 말해 주나요? 5.2 의 「보낼 곳」 표와 이어서 설명하세요.
  - 답: 두 주소가 일치하므로 다른 망이나 인터넷으로 가는 패킷의 첫 홉은 기본 게이트웨이 `192.168.1.1`입니다. 5.2의 표처럼 목적지가 내 망 밖에 있으면 PC는 프레임을 게이트웨이의 MAC 주소로 보내고, 게이트웨이가 다음 망으로 전달합니다.
- (나-2) 두 주소가 일치하지 않는다면 어떤 상황을 의심해야 하나요? 근거와 함께 설명하세요.
  - 답: 먼저 `ipconfig`에서 다른 네트워크 어댑터의 게이트웨이를 확인한 것은 아닌지 살펴봅니다. 같은 어댑터 기준인데도 다르면 VPN이나 별도의 라우팅 설정 때문에 다른 장비가 첫 홉이 되는지, 게이트웨이 설정이 잘못되었거나 예상하지 않은 장비를 거치는지 확인해야 합니다. 기본 경로의 다음 홉이 보통 기본 게이트웨이이므로 두 주소가 다르면 경로 설정을 점검할 근거가 됩니다.
- (다-1) 기본 경로(`0.0.0.0/0`)는 어떤 목적지로 갈 때 쓰이나요?
  - 답: 라우팅 표에서 더 구체적으로 일치하는 경로가 없는 목적지로 패킷을 보낼 때 사용합니다. 보통 인터넷처럼 내 망 바깥의 주소로 갈 때 이 경로를 통해 기본 게이트웨이에 전달합니다.
- (다-2) 기본 경로의 `/0` 은 무엇을 뜻하나요?
  - 답: 망 부분으로 비교하는 비트가 0개라는 뜻입니다. 특정 네트워크 주소 비트를 요구하지 않아 모든 IPv4 주소와 일치합니다.
- (다-3) 라우팅 표에서 기본 경로가 빠지면 맞는 줄이 없는 목적지로 가는 패킷은 어떻게 되나요?
  - 답: 패킷의 목적지와 일치하는 경로가 없으므로 다음 홉을 정할 수 없습니다. 패킷은 전달되지 않고 버려지며, PC나 라우터에서 도달할 수 없다는 오류가 날 수 있습니다.
- (다-4) 이때 같은 망 통신과 인터넷 통신이 각각 어떻게 되는지 이유와 함께 설명하세요.
  - 답: 같은 망 통신은 직접 연결된 망 경로가 라우팅 표에 남아 있으므로 계속 가능합니다. 인터넷 통신은 목적지에 맞는 더 구체적인 경로가 없고 기본 경로도 빠져 있어 다음 홉을 찾지 못하므로 되지 않습니다.

### 문제 6-2 · 회사 망 줄인가, 기본 경로인가

- (가-1) 첫 파일 출력: `맞는 줄: 192.168.30.0/24 → 직접 연결 VLAN 30`
- (가-2) 두 번째 파일(`8.8.8.8`) 출력: `회사 망 줄에 없음 → 기본 경로 0.0.0.0/0 (인터넷 쪽 라우터)`
- (나-1) 라우터가 `192.168.30.5` 를 보낼 줄을 고르는 과정을 6.3 의 라우팅 표와 첫 파일 출력으로 설명하세요.
  - 답: 라우터는 목적지 `192.168.30.5`가 회사 망 줄 가운데 어디에 속하는지 차례로 확인합니다. 이 주소는 `192.168.30.0/24`에 들어가므로 세 번째 줄과 일치하며, 출력처럼 직접 연결된 VLAN 30으로 보냅니다.
- (나-2) `8.8.8.8` 일 때 `found` 가 반복이 끝날 때까지 `False` 로 남은 이유를 설명하세요.
  - 답: `8.8.8.8`은 `192.168.10.0/24`, `192.168.20.0/24`, `192.168.30.0/24` 중 어느 회사 망에도 속하지 않습니다. 반복문 안에서 일치하는 줄을 찾지 못해 `found = True`가 실행되지 않으므로 `False`로 남습니다.
- (나-3) 그것이 라우터가 기본 경로 줄을 고르는 조건과 어떻게 대응하는지 설명하세요.
  - 답: `found`가 `False`로 남았다는 것은 목적지에 맞는 회사 망 줄이 없다는 뜻입니다. 이는 6.3 표의 조건인 “회사 망 줄에 맞지 않으면 기본 경로를 사용한다”에 해당하므로, 라우터는 `0.0.0.0/0`을 따라 인터넷 쪽 라우터로 보냅니다.
- (다) 부서마다 VLAN 을 나누면 한 부서 PC 가 악성코드에 감염됐을 때 피해 범위와 대응 방법이 어떻게 달라지나요? 브로드캐스트 범위와 라우터에서의 접근 통제를 들어 설명하세요.
  - 답: VLAN마다 브로드캐스트가 분리되므로 감염된 PC의 브로드캐스트 트래픽은 우선 그 부서 VLAN 안에 머물러 다른 부서로 바로 퍼지지 않습니다. 부서 사이 통신은 라우터를 거치므로, 라우터의 접근 통제 규칙으로 감염된 VLAN에서 다른 부서나 인터넷으로 가는 통신을 제한해 피해를 줄일 수 있습니다.

### 이 교시에 새로 안 것

- 이 교시에서 새로 알게 된 것: 라우터는 목적지가 속한 회사 망 경로를 먼저 찾고, 해당 경로가 없으면 기본 경로로 보낸다는 것을 알게 되었다. VLAN은 부서별 브로드캐스트 범위를 나누며, 라우터의 접근 통제로 부서 사이 통신을 제한할 수 있다.

### 문제 7-2 · 서브넷 마스크 다시 보기

- (가) 세 마스크의 CIDR · 주소 수: `255.255.0.0` = `/16`, 65,536개 · `255.255.255.0` = `/24`, 256개 · `255.255.255.128` = `/25`, 128개
- (나) 서브넷 마스크는 IP 주소에서 무엇을 정하는 값인가요? 마스크를 2진수로 썼을 때 1 과 0 이 각각 무엇을 뜻하는지 넣어 설명하세요.
  - 답: 서브넷 마스크는 IP 주소에서 망 부분과 장비 부분을 나눕니다. 2진수 마스크에서 1인 자리는 망 부분, 0인 자리는 장비 부분을 나타냅니다. 예를 들어 `/24`는 앞 24비트가 망 부분이고 나머지 8비트가 장비 부분입니다.
- (다) `172.16.8.40` 과 `172.16.9.40` 은 마스크가 `255.255.255.0` 이면 다른 망, `255.255.0.0` 이면 같은 망입니다. 같은 두 주소인데 판정이 달라지는 이유를 망 부분으로 설명하세요.
  - 답: `255.255.255.0`(`/24`)에서는 앞 세 마디가 망 부분이므로 `172.16.8`과 `172.16.9`가 달라 두 주소는 다른 망입니다. `255.255.0.0`(`/16`)에서는 앞 두 마디만 망 부분이고 둘 다 `172.16`으로 같으므로 같은 망입니다.
- (라) 원래 `/24` 로 써야 하는 PC 에 실수로 `255.255.0.0` 을 설정하면, 그 PC 가 `172.16.9.40` 으로 보낼 때 어떤 문제가 생길지 게이트웨이와 이어서 설명하세요.
  - 답: 잘못 설정한 PC는 `/16` 기준으로 `172.16.9.40`을 같은 망이라고 판단해 게이트웨이로 보내지 않고 직접 찾으려 합니다. 하지만 상대는 원래 `/24`의 다른 망에 있으므로 PC가 ARP로 같은 망에서 상대를 찾으려 해도 도달하지 못할 수 있습니다. 그 결과 라우터의 게이트웨이를 거치지 않아 통신이 실패합니다.

## 최종 설계서 — 7교시에 완성합니다

> 오늘 설계한 회사망을 정리합니다. 5.2 · 6.3 의 표와 위에서 적은 6-2 의 답을 다시 보며 씁니다.

### 1. 부서마다 망 · VLAN · 게이트웨이 — 5.2 · 6.1 · 6.3

- 세 부서의 망 · VLAN · 게이트웨이: 개발팀 `192.168.10.0/24` · VLAN 10 · 게이트웨이 `192.168.10.1`; 운영팀 `192.168.20.0/24` · VLAN 20 · 게이트웨이 `192.168.20.1`; 보안팀 `192.168.30.0/24` · VLAN 30 · 게이트웨이 `192.168.30.1`
- 부서마다 VLAN 하나에 서브넷 하나를 맞춘 이유를, 서로 다른 VLAN 에 같은 서브넷을 주었을 때 PC 와 스위치가 각각 어떻게 동작하는지와 견주어 설명하세요.
  - 답: VLAN은 스위치에서 브로드캐스트가 전달되는 범위를 나누고, 서브넷은 IP 통신에서 같은 망인지 판단하는 범위를 정합니다. VLAN 하나에 서브넷 하나를 맞추면 같은 서브넷의 PC는 같은 VLAN 안에서 직접 통신하고, 다른 서브넷과는 게이트웨이를 통해 통신하므로 경로와 접근 통제를 명확히 할 수 있습니다. 서로 다른 VLAN에 같은 서브넷을 설정하면 PC는 상대를 같은 망으로 판단해 게이트웨이 대신 ARP로 직접 찾으려 하지만, 스위치는 VLAN 사이로 브로드캐스트를 전달하지 않아 상대를 찾지 못하고 통신이 실패할 수 있습니다.

### 2. 라우팅 경로 — 6-2

- 운영팀 PC `192.168.20.30` → 인터넷 `8.8.8.8` 이 지나는 장비와, 라우터가 그때 쓴 라우팅 표의 줄: 운영팀 PC → 스위치(VLAN 20) → 게이트웨이/회사 라우터 `192.168.20.1` → 인터넷 쪽 라우터. 회사 라우터의 `0.0.0.0/0` 기본 경로를 사용합니다.
- 라우터가 6-2 의 `192.168.30.5`(보안팀 PC)와 이 통신(`8.8.8.8`)에서 다음 홉을 다르게 고른 이유를, 라우팅 표에서 맞는 줄을 찾는 순서로 설명하세요.
  - 답: 라우터는 먼저 목적지가 들어가는 회사 망 줄이 있는지 확인합니다. `192.168.30.5`는 `192.168.30.0/24`에 속하므로 직접 연결 VLAN 30으로 보내지만, `8.8.8.8`은 회사의 세 `/24` 망 어디에도 속하지 않으므로 기본 경로 `0.0.0.0/0`을 골라 인터넷 쪽 라우터로 보냅니다.

### 3. 오늘 하루 정리

- 오늘 배운 것 가운데 가장 중요하다고 생각하는 것과 그 이유: 서브넷 마스크와 라우팅 경로를 함께 이해하는 것이 가장 중요하다고 생각한다. 마스크에 따라 목적지가 같은 망인지 달라지고, 그 판단에 따라 PC가 직접 보내거나 게이트웨이를 거치기 때문이다. 이를 알아야 통신 장애의 원인을 찾고 잘못된 경로 설정을 점검할 수 있다.
