# 정산 포털 정책 로그 점검 결과
## 결론
- 정책 판단과 앱의 실제 응답이 일치하지 않은 사례 3건(101·108·112)과 정책 기록 없이 앱에서 처리된 요청 1건(201)이 확인됐다. 기록만으로 계정 도용이나 고의 우회 여부까지는 확인할 수 없으며, 실제 집행 경로와 요청 출처를 추가 조사해야 한다.
## 근거
- 3-1 비교에서 101은 PDP가 거부했지만 앱은 200(통과), 108은 추가 확인을 요구했지만 앱은 200(통과)으로 응답했다. 두 건은 정해진 응답보다 약하게 처리된 집행 누락(정책보다 약하게 적용된 경우)이다.
- 3-1 비교에서 112는 PDP가 허용했지만 앱은 403(차단)으로 응답해 과집행(정책보다 강하게 막은 경우)으로 분류됐다. 요청 201은 정책 로그에 없지만 앱 기록에는 200으로 남아 정책 판단 기록과 짝을 찾을 수 없는 요청, 즉 이 점검 기준의 우회(정책 기록 없이 앱에서 처리된 요청)로 분류됐다. 이 분류만으로 고의성은 확인되지 않는다.
- 4-1 점수 비교에서 현재 규칙은 오탐 6건·미탐 0건, 안 A는 오탐 0건·미탐 1건이었다. 안 A의 미탐은 요청 11(해외 49건 조회)이며 점수 30으로 거부가 아닌 추가 확인에 그쳤다.
## 권고
- PEP(정책 판단을 앱의 실제 허용·차단 응답으로 적용하는 지점)의 요청 추적 로그, 정책 전달·캐시 기록, 응답 매핑과 배포 설정을 확인해 101·108·112의 불일치 원인을 찾는다. 201은 요청 출처·인증·라우팅 기록과 정책 로그 수집 누락 여부를 대조해 고의 우회인지 기록 연계 문제인지 확인한다.
- 오탐을 줄이기 위해 안 A를 검토하되, 적용 전에 해외 49건 조회(11번)처럼 대량 조회 기준 바로 아래의 위험 요청을 보완할 별도 탐지·차단 규칙을 마련하고 시험한다. 안 A는 오탐을 6건에서 0건으로 줄이는 대신 미탐 1건을 만든다.
