## 5교시 · 왜 도커인가 · 이미지와 컨테이너 · 같이 설치하기

### 문제 5-1 · 설치를 확인하고 첫 컨테이너 실행하기

- (가) `docker --version` 으로 나온 값을 적어 주세요.
  - 쓸 내용: 「Docker version … build …」 한 줄
  - 답: Docker version 29.8.2, build 7fc2dff
- (나) 🔍 `docker run hello-world` 출력이 말하는 일의 순서를 5.5 그림의 번호(① ~ ④)에 맞춰 설명해 주세요.
  - 쓸 내용: ① ~ ④ 번호마다 한 일 (클라이언트 · 엔진 · Docker Hub · 컨테이너)
  - 답: ① Docker 클라이언트가 Docker 엔진(daemon)에 연결한다. ② 엔진이 로컬에 이미지가 없음을 확인하고 Docker Hub에서 `hello-world:latest` 이미지를 내려받는다. ③ 엔진이 이미지로 새 컨테이너를 만들어 실행한다. ④ 엔진이 컨테이너의 출력 결과를 클라이언트로 보내고, 클라이언트가 터미널에 보여 준다.
- (다) 🔍 `docker images` 에 보인 것과 `docker ps -a` 에 보인 것은 각각 이미지와 컨테이너 중 무엇이고, 어떻게 다른가요?
  - 쓸 내용: ① images 에 보인 것과 그 종류 ② ps -a 에 보인 것과 그 종류 ③ 둘의 차이
  - 답: `docker images`에는 컨테이너를 만들 때 쓰는 이미지인 `hello-world:latest`가 보인다. `docker ps -a`에는 그 이미지로 만들어 실행한 컨테이너가 보인다. 이미지는 실행에 필요한 파일과 설정을 담은 재료이고, 컨테이너는 그 이미지를 실행한 인스턴스다. `-a` 옵션을 사용했기 때문에 실행이 끝난 컨테이너도 목록에 남아 있다.
- (라) 🔍 `docker images` 출력을 붙여 넣고, `hello-world` 줄의 `IMAGE` · `ID` · `EXTRA` 값과 각각의 뜻을 적어 주세요.
  - 쓸 내용: ① 출력 ② `IMAGE` · `ID` · `EXTRA` 의 값과 뜻
  - 답: `IMAGE`는 `hello-world:latest`(이미지 이름과 태그), `ID`는 `11a3eb1597e8`(이미지의 고유 ID)이다. 안내서의 `EXTRA` 열은 내 Docker 출력에 없고, 대신 `DISK USAGE`와 `CONTENT SIZE`가 표시됐다. 출력 위쪽의 `U In Use`는 사용 중인 이미지 표시 안내지만, 이 이미지 행에는 `U` 표시가 나타나지 않았다.

```
                                      i Info →   U  In Use
IMAGE              ID             DISK USAGE   CONTENT SIZE
hello-world:latest
                   11a3eb1597e8       25.9kB         9.49kB
```

- (마) 🔍 `docker ps -a` 출력을 붙여 넣고, `hello-world` 줄의 `STATUS` · `PORTS` · `NAMES` · `IMAGE` 값과 각각의 뜻을 적어 주세요.
  - 쓸 내용: ① 출력 ② `STATUS` · `PORTS` · `NAMES` · `IMAGE` 의 값과 뜻
  - 답: `STATUS`는 `Exited (0)`으로 컨테이너가 오류 없이 종료됐다는 뜻이다. `PORTS`는 비어 있어 연결된 포트가 없다. `NAMES`는 `nostalgic_lederberg`로, Docker가 자동으로 붙인 컨테이너 이름이다. `IMAGE`는 `hello-world`로 이 컨테이너를 만든 이미지다.

```
CONTAINER ID   IMAGE         COMMAND    CREATED  STATUS                          PORTS     NAMES
f6064c5f3293   hello-world   "/hello"   About a minute ago  Exited (0) About a minute ago             nostalgic_lederberg
```


### 문제 5-2 · Docker Hub 에서 이미지 이름 읽고 없는 이미지 받아 보기

- (가) `nginx:1.28` 에서 `nginx` 와 `1.28` 이 각각 무엇을 정하는지 적어 주세요.
  - 쓸 내용: ① nginx 가 정하는 것 ② 1.28 이 정하는 것
  - 답: `nginx`는 이미지 이름이고, `1.28`은 사용할 이미지의 버전(태그)이다. `docker pull nginx:1.28` 실행 결과 `nginx:1.28` 이미지가 Docker Hub에서 정상적으로 내려받아졌다.
- (나) 🔍 `docker pull nginxx` 를 쳤을 때 나온 오류 문구와 그 뜻을 적어 주세요.
  - 쓸 내용: ① 오류 문구 ② 뜻 ③ 고치는 방법
  - 답: 오류 문구는 `pull access denied for nginxx, repository does not exist or may require 'docker login'`이다. Docker Hub에서 `nginxx`라는 저장소/이미지를 찾을 수 없거나 접근할 수 없다는 뜻이다. 이름을 올바른 `nginx`로 고쳐 `docker pull nginx:1.28`을 실행하면 된다. 실제로 이 명령은 성공해 `nginx:1.28`을 내려받았다.
- (한 줄) 보안 담당에게 보낼 답을 한 문장으로 적어 주세요.
  - 쓸 내용: 보안 담당이 바로 읽을 수 있는 한 문장(도커를 쓰면 무엇이 같아지는지)
  - 답: Docker 이미지와 버전을 지정해 사용하면 팀원 PC와 서버에서 같은 애플리케이션 실행 환경을 재현하기 쉬워집니다.
- 이 교시에서 새로 알게 된 것 하나를 적어 주세요.
  - 쓸 내용: 자유롭게
  - 답: 이미지 이름 뒤에 콜론과 태그를 붙여 버전을 지정할 수 있고, 이미지 이름을 잘못 입력하면 Docker Hub에서 이미지를 찾지 못한다는 것을 알게 되었다.

## 6교시 · nginx 서버 켜고 접속 기록 읽기

### 문제 6-1 · 포트 없이 켜 보고, 포트를 연결해 접속하고, 기록 읽기

- (가) 포트 없이 켠 `web` 에 접속했을 때 어떻게 되었는지 적어 주세요.
  - 쓸 내용: 접속했을 때 나온 화면이나 오류와 `docker ps` 의 PORTS 열
  - 답: 포트 연결 없이 실행했을 때 `docker ps`의 `PORTS`에는 `80/tcp`만 표시되고 내 PC의 포트로 연결하는 `->`가 없었다. 따라서 브라우저에서 `http://127.0.0.1:8080`으로 접속할 수 없는 상태였다.
- (나) 🔍 `-p 8080:80` 이 하는 일을 내 PC의 포트와 컨테이너의 포트로 나눠 설명해 주세요.
  - 쓸 내용: ① 내 PC 쪽 포트 ② 컨테이너 쪽 포트 ③ 연결이 하는 일
  - 답: `-p 8080:80`에서 `8080`은 내 PC 쪽 포트이고 `80`은 nginx 컨테이너 안의 포트다. 두 포트를 연결하므로 브라우저가 내 PC의 `http://127.0.0.1:8080`에 보낸 요청을 컨테이너의 nginx 80번 포트로 전달한다. 실제 `docker ps`에는 `0.0.0.0:8080->80/tcp`와 `[::]:8080->80/tcp`로 표시됐다.
- (다) 🔍 `docker logs web` 출력에서 `GET /` 줄 하나를 붙여 넣고, 접속자 주소 · 시각 · 요청 · 응답 번호를 찾아 적어 주세요.
  - 쓸 내용: ① `GET /` 줄 ② 접속자 주소 · 시각 · 요청 · 응답 번호 네 가지
  - 답: 접속 기록은 아래와 같다. 접속자 주소는 `172.17.0.1`, 시각은 `19/Oct/2026:06:02:39 +0000`, 요청은 `GET / HTTP/1.1`, 응답 번호는 `200`이다. `200`은 요청이 정상 처리됐다는 뜻이다.

```
172.17.0.1 - - [19/Oct/2026:06:02:39 +0000] "GET / HTTP/1.1" 200 615 "-" "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/155.0.0.0 Safari/537.36" "-"
```

### 문제 6-2 · 컨테이너 안을 들여다보고, 끄고, 지우기

- (가) 컨테이너 안에서 `ls /usr/share/nginx/html` 로 본 파일 이름을 모두 적고, 그중 브라우저의 첫 화면이 어느 파일인지 적어 주세요.
  - 쓸 내용: ① 파일 이름 모두 ② 첫 화면 파일
  - 답: `50x.html`, `index.html` 두 파일이 있었다. 브라우저에서 `/`로 접속했을 때 나오는 Welcome to nginx! 첫 화면은 `index.html`이다.
- (나) 🔍 `docker stop web` 뒤에 `docker ps` 와 `docker ps -a` 에 각각 `web` 이 보이나요? 차이를 설명해 주세요.
  - 쓸 내용: ① stop 뒤 ps 에 보이는지 ② ps -a 에 보이는지 ③ 차이의 이유
  - 답: `docker stop web` 뒤 `docker ps`에는 `web`이 보이지 않았고, `docker ps -a`에는 `web`이 `Exited (0)` 상태로 보였다. `docker ps`는 실행 중인 컨테이너만 보여 주지만 `docker ps -a`는 중지된 컨테이너까지 모두 보여 주기 때문이다.
- (다) 🔍 같은 이름으로 다시 `run` 했을 때 나온 오류 문구와, `docker rm` 이 필요한 이유를 적어 주세요.
  - 쓸 내용: ① 오류 문구 ② rm 이 필요한 이유
  - 답: 다시 실행했을 때 `Conflict. The container name "/web" is already in use` 오류가 나왔다. `docker stop`은 컨테이너를 멈출 뿐 삭제하지 않으므로, 중지된 `web` 컨테이너가 같은 이름을 계속 차지한다. `docker rm web`으로 기존 컨테이너를 삭제한 뒤 같은 이름으로 새 컨테이너를 만들 수 있었다. 삭제 후 `docker stop web`이나 `docker rm web`을 다시 실행하면 `No such container: web`이 나오는데, 이미 삭제되어 해당 컨테이너가 없다는 뜻이다.
- (한 줄) 보안 담당에게 보낼 답을 한 문장으로 적어 주세요.
  - 쓸 내용: 보안 담당이 바로 읽을 수 있는 한 문장(켜는 명령 · 기록 보는 명령 · 정리 방법)
  - 답: nginx 서버는 `docker run -d --name web -p 8080:80 nginx:1.28`로 켜고 `docker logs web`으로 접속 기록을 확인하며, 중지한 컨테이너는 `docker rm web`으로 삭제해 이름을 다시 사용할 수 있습니다.
- 이 교시에서 새로 알게 된 것 하나를 적어 주세요.
  - 쓸 내용: 자유롭게
  - 답: 컨테이너를 중지해도 삭제되지는 않아 이름이 계속 사용 중일 수 있고, `docker ps -a`로 확인한 뒤 `docker rm`으로 지워야 같은 이름으로 다시 만들 수 있다는 것을 알게 되었다.

## 7교시 · 내 페이지 연결 · 두 서버 · 올리기

### 문제 7-1 · 컨테이너 안의 변경이 사라지는 것을 보고, 내 폴더를 연결하기

- (가) 컨테이너 안에서 바꾼 뒤 `docker rm -f web` 으로 지우고 다시 켰을 때 화면이 어떻게 되었는지 적어 주세요.
  - 쓸 내용: ① 바꾼 뒤 화면 ② 지우고 다시 켠 뒤 화면
  - 답: 컨테이너 안에서 `index.html`을 `<h1>inside</h1>`로 바꾼 뒤 파일 내용을 확인해 `inside`가 저장된 것을 봤다. 기존 `web`을 지우고 같은 이미지로 새 컨테이너를 실행하면 이미지의 원래 파일로 시작하므로 브라우저에는 `Welcome to nginx!`가 다시 나온다. 공유한 터미널 결과에는 브라우저 화면 자체는 포함되어 있지 않다.
- (나) 🔍 컨테이너 안에서 바꾼 내용이 사라진 이유와, `-v` 로 폴더를 연결하면 무엇이 달라지는지 적어 주세요.
  - 쓸 내용: ① 사라진 이유 ② -v 로 연결하면 달라지는 점
  - 답: 수정한 파일은 이미지가 아니라 기존 컨테이너 안에 저장됐기 때문에 컨테이너를 삭제하자 함께 사라졌다. `-v`로 내 PC의 `site-one` 폴더를 컨테이너의 웹 폴더에 연결하면 웹 파일이 내 PC에 남고, 컨테이너를 새로 만들어도 같은 파일을 사용할 수 있다.
- (다) 🔍 `MSYS_NO_PATHCONV=1` 없이 `-v` 를 실행했을 때 화면에 무엇이 나왔고 왜 그랬는지 적어 주세요.
  - 쓸 내용: ① 화면에 나온 것 ② 그렇게 된 이유
  - 답: 공유한 결과에서는 `docker run`이 컨테이너 ID를 출력했고 `docker ps`에는 `web-one`이 `Up`으로 표시됐다. 브라우저 화면은 기록에 없어 실제로 무엇이 보였는지는 확인할 수 없다. 실습 안내의 Git Bash 예상 결과는 `Welcome to nginx!`이며, Git Bash의 경로 변환 때문에 `-v`의 컨테이너 쪽 경로가 바뀌어 `site-one/index.html` 대신 nginx 이미지의 기본 페이지가 보이는 상황이다. 확인하려면 브라우저에서 `http://127.0.0.1:8080`을 열어야 한다.

### 문제 7-2 · 서버 두 대를 띄워 포트로 구분하고, 파일을 고쳐 바로 반영되는지 보기

- (가) 두 주소(`8080` · `8081`)에서 보이는 화면을 각각 적어 주세요.
  - 쓸 내용: 두 주소의 화면 문구
  - 답: `http://127.0.0.1:8080`은 `site-one` 제목과 「첫 번째 서버입니다」 문구를 보여 주고, `http://127.0.0.1:8081`은 `site-two` 제목과 「두 번째 서버입니다」 문구를 보여 준다. 두 HTML 파일 내용과 두 컨테이너의 실행은 확인했지만, 공유한 기록에는 브라우저 화면을 연 결과가 포함되어 있지 않다.
- (나) 🔍 `docker ps` 의 PORTS 열에서 두 서버를 구분해 주는 것은 무엇인가요?
  - 쓸 내용: PORTS 열에서 서버를 구분하는 값
  - 답: 내 PC 쪽 포트 번호다. `web-one`은 `0.0.0.0:8080->80/tcp`, `web-two`는 `0.0.0.0:8081->80/tcp`로 표시된다. 컨테이너 안의 nginx 포트는 둘 다 80번이고, PC 쪽 포트 8080과 8081로 각각 구분한다.
- (다) 🔍 `:ro` 는 무슨 뜻이고, 왜 읽기 전용으로 연결하나요?
  - 쓸 내용: ① :ro 의 뜻 ② 읽기 전용으로 연결하는 이유
  - 답: `:ro`는 `read-only`의 약자로 컨테이너가 연결된 내 PC 폴더를 읽기만 하고 수정하지 못하게 한다. 웹 서버가 페이지 파일을 임의로 바꾸지 못하게 보호하고, 수정은 내 PC의 파일에서 하도록 하기 위해 읽기 전용으로 연결한다.
- (한 줄) 보안 담당에게 보낼 답을 한 문장으로 적어 주세요.
  - 쓸 내용: 보안 담당이 바로 읽을 수 있는 한 문장(두 서버를 어떻게 띄웠는지)
  - 답: 같은 `nginx:1.28` 이미지로 컨테이너 두 개를 실행하고, 각각 다른 PC 폴더를 읽기 전용으로 연결한 뒤 PC 포트 8080과 8081로 나눠 접속합니다.
- 이 교시에서 새로 알게 된 것 하나를 적어 주세요.
  - 쓸 내용: 자유롭게
