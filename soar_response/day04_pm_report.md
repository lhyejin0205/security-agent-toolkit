  - 답: TCK-1은 20분에 응답 기한 15분을 5분 넘겨 1단계로 올려졌다. 25분에 `kim.sec`이 상태를 `확인 중`으로 바꿨고, `needs_escalation`은 티켓 상태가 `열림`이 아니면 `False`를 반환하므로 60분 점검에서는 제외됐다. 이 조건이 없다면 이미 확인 중인 티켓을 계속 상급자에게 알리게 되어 불필요한 알림과 알림 피로가 생긴다.

- (다) 🔍 110분 점검에서 `TCK-3` 은 2단계로, `TCK-6` 은 1단계로 에스컬레이션되었습니다. 두 티켓의 응답 기한과 초과 시간을 근거로 단계가 달라진 이유를 설명해 주세요. 또한 등급 low 인 `TCK-2` 가 에스컬레이션되지 않은 이유도 설명해 주세요.
  - 쓸 내용: ① TCK-3 · TCK-6 의 응답 기한과 넘긴 시간 ② 단계가 달라진 이유 ③ TCK-2 가 에스컬레이션되지 않은 이유
  - 답: TCK-3의 응답 기한은 68분이므로 110분 점검 때 42분 초과했고, 30분 이상 초과했으므로 2단계(`soc.head`)로 올려졌다. TCK-6의 응답 기한은 95분이므로 15분 초과해 1단계(`team.lead`)로 올려졌다. TCK-2는 low 등급으로 응답 기한이 243분이어서 110분에는 아직 기한이 지나지 않았다.

## 6교시 · 근무 3시간 시뮬레이션을 연속 실행하고 MTTA(평균 확인 시간) · MTTR(평균 해결 시간) · 응답 기한 위반 수 산출하기

### 문제 6-1 · 근무 3시간 시뮬레이션을 실행하고 MTTA · MTTR · 응답 기한 위반 수 산출하기

- (가) 실행한 출력 전체를 붙여 넣어 주세요. 그리고 그 출력에서 MTTA(평균 확인 시간) · MTTR(평균 해결 시간) · 응답 기한을 넘긴 티켓 수(응답 기한 위반 수)를 찾아 적어 주세요.
  - 쓸 내용: ① 출력 전체(코드 상자에 붙여 넣기) ② MTTA(평균 확인 시간) ③ MTTR(평균 해결 시간) ④ 응답 기한을 넘긴 티켓 수
  - 답:

TCK-7 [high] dami — 퇴사한 계정 · 상태 확인 중 · 조치 결과가 맞는지 확인하고 계정이나 IP 상태를 점검한다

MTTA는 **55.0분**, MTTR은 **84.0분**, 응답 기한 위반은 **2장**이다. 알림 서버에는 새 `[알림 받음]`이 **12줄** 추가됐다.

- (나) 🔍 확인된 티켓 `TCK-1` · `TCK-3` · `TCK-4` · `TCK-6` · `TCK-7` 의 확인 시간(확인 시각 − 생성 시각)을 각각 계산하고, 그 평균인 MTTA(평균 확인 시간)를 직접 계산해 적어 주세요. 또한 미확인 티켓인 `TCK-2` · `TCK-5` 를 평균에서 제외하는 이유도 설명해 주세요.
  - 쓸 내용: ① 확인한 티켓 5장의 확인 시간 계산 ② 평균 ③ 확인하지 않은 티켓을 뺀 이유
  - 답: 확인 시간은 TCK-1 `10 - 0 = 10분`, TCK-3 `80 - 8 = 72분`, TCK-4 `140 - 12 = 128분`, TCK-6 `90 - 35 = 55분`, TCK-7 `105 - 95 = 10분`이다. 합계 275분을 5장으로 나누면 MTTA는 `55.0분`이다. TCK-2와 TCK-5는 아직 확인되지 않아 측정된 확인 시간이 없다. 이를 0분으로 포함하면 평균이 실제보다 낮아져 대응이 빨랐던 것처럼 왜곡된다.

- (다) 🔍 응답 기한을 위반한 티켓 2장이 어느 티켓인지 적어 주세요. 이때 각 티켓의 `sla_due` 와 확인 시각을 근거로 씁니다. 그리고 단계 1 의 70분 · 80분 · 110분에 출력된 줄(상급자에게 올림 · 확인 중)이 이 두 티켓과 어떤 관계인지 설명해 주세요.
  - 쓸 내용: ① 기한을 넘긴 티켓과 `sla_due` · 확인한 시각 ② 단계 1 의 70분 · 80분 · 110분 줄과의 관계
  - 답: 응답 기한 위반은 TCK-3과 TCK-4다. TCK-3은 `sla_due` 68분보다 늦은 80분에 확인되어 12분 초과했고, TCK-4는 `sla_due` 72분보다 늦은 140분에 확인되어 68분 초과했다. TCK-3은 70분 점검에서 2분 초과로 1단계에 올려진 뒤 80분에 확인됐다. TCK-4는 80분 점검에서 8분 초과로 1단계, 110분 점검에서 38분 초과로 2단계에 올려졌고 140분에 확인됐다. 에스컬레이션은 미확인 상태로 점검 시각까지 남은 티켓에 대한 알림이고, SLA 위반은 실제 확인 시각이 기한보다 늦었는지를 보는 지표다.
